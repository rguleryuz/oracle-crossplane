# Crossplane on k3s with OCI NoSQL (Always Free) — Design

Date: 2026-09-21
Status: Approved (design sections confirmed in chat)

## Goal

Learn Crossplane hands-on via a GitOps repo: Flux on a self-hosted k3s
cluster manages Crossplane, which provisions an Always Free OCI NoSQL
table via a composition + claim.

## Context

- **Cluster:** self-hosted k3s `k3s-arm-cluster`, v1.36.4+k3s1, ARM64
  (Oracle Ampere), single node, reachable from this machine
  (`https://141.144.234.213:6443`).
- **Repo:** `oracle-crossplane/`, hosted public on GitHub.
- **GitOps engine:** Flux (bootstrap via `flux bootstrap github`).
- **Crossplane:** v2 (namespaced managed resources).
- **OCI provider:** official Upjet-generated family sub-provider
  `ghcr.io/oracle/provider-oci-nosql:v1.4.0`
  (from github.com/oracle/crossplane-provider-oci).
- **Composition function:** `function-patch-and-transform`.

## Architecture

```
GitHub repo (public)
      │  flux bootstrap github
      ▼
k3s ── Flux (source / kustomize / helm controllers)
      ├── Crossplane (HelmRelease, ns crossplane-system)
      ├── provider-oci-nosql (Provider package → CRDs + controller)
      ├── ProviderConfig (creds via SecretRef)
      ├── XRD + Composition (platform definition)
      └── Claim (namespaced) → XR → NoSQL Table managed resource
                                        │
                                        ▼
                            OCI NoSQL Table (Always Free)
```

Two layered control loops: Flux reconciles git → cluster; Crossplane
reconciles XR → OCI API. Connection details (table OCID, endpoint) flow
back into a k8s Secret for consuming apps.

## Components

### Crossplane install

HelmRepository (crossplane stable) + HelmRelease into
`crossplane-system`, latest stable v2.x chart.

### OCI provider

- `Provider` manifest referencing `ghcr.io/oracle/provider-oci-nosql:v1.4.0`.
- `ProviderConfig` with `credentials.source: Secret`, referencing
  `oci-creds` in `crossplane-system`.
- `function-patch-and-transform` installed as a `Function` package.

### XRD `XNoSQLTable` (namespaced, Crossplane v2)

Exposes to app developers only:

- `tableName` (string, required)
- `ddl` (string, required) — NoSQL DDL statement

Does NOT expose capacity fields — free-tier caps cannot be overridden.

### Composition

Maps XR → `Table` managed resource. Hardcodes:

- `maxReadUnits: 50`
- `maxWriteUnits: 50`
- `maxStorageInGBs: 25`
- `isAutoReclaimable: true`

Patches `tableName` and `ddl` from the XR; compartment OCID patched from
a fixed value in the composition (documented, changeable via git).

### Claim

Demo claim in namespace `demo`: requests a table, receives connection
secret with table OCID / endpoint in the same namespace.

## OCI prerequisites (manual, one-time)

1. Create compartment `crossplane-demo`; record OCID.
2. Create API key on OCI user; record tenancy OCID, user OCID,
   fingerprint, private key PEM.
3. IAM policy: `Allow group <group> to manage nosql-family in
   compartment crossplane-demo` (adjust to actual group/user).
4. Create secret imperatively (never committed):

   ```bash
   kubectl -n crossplane-system create secret generic oci-creds \
     --from-file=credentials=oci-api-key.ini
   ```

   `.gitignore` excludes `*.pem`, `*.ini`, and any creds files.

### Free-tier safety

Always Free NoSQL = max 3 tables/region, fixed 50 read units, 50 write
units, 25 GB storage per table. Composition pins limits at the free
caps, so a claim cannot create a paid table. XRD validation rejects
attempts to pass capacity fields (they are not in the schema).

**Warning:** `isAutoReclaimable: true` means OCI deletes the table and
its data after 90 days with no reads or writes. Acceptable for learning;
documented in README.

## Secrets strategy

Imperative secret (chosen over SOPS for v1). Nothing sensitive enters
git. Upgrade path to SOPS + age noted in README as future work.

## Verification plan

1. `flux get sources all` / `flux get kustomizations` — all Ready.
2. `kubectl get providers` — INSTALLED=True, HEALTHY=True.
3. `kubectl get claim -n demo` and the XR — READY=True.
4. `kubectl get table.nosql.oci.upbound.io` — SYNCED=True, READY=True.
   (Exact group confirmed against installed CRD at implementation time.)
5. OCI console: table exists with Always Free badge.
6. Negative test: `kubectl delete claim` → managed resource finalized
   and table deprovisioned in OCI.

## Error handling

- Flux retries failed Kustomizations; `flux logs` and
  `kubectl describe` surface failures.
- Crossplane reconcile errors visible via `kubectl describe` on XR and
  managed resource, plus provider pod logs.
- Rollback = git revert; Flux converges cluster back.

## Risks

- 90-day inactivity auto-reclaim (inherent to Always Free).
- k3s node needs outbound 443 to OCI API endpoints (verify at
  implementation).
- ARM64 node: provider images must have arm64 manifests (Oracle
  publishes multi-arch; verify at implementation — fall back to
  pinning a version with arm64 support).

## Out of scope (YAGNI)

- SOPS/Sealed Secrets, OKE workloads, multiple environments,
  monitoring/alerting, more than one claim/table.
